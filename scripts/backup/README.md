# النسخ الاحتياطي والاستعادة — بند 7.1 (O4 وT6)

نسخة مشفّرة أسبوعية وقبل كل نشر، وتمرين استعادة شهري، و«آخر نسخة» ظاهرة للمالك في الإدارة من حالة
موثّقة في قاعدة البيانات (ترحيل 0103). لا مفاتيح ولا عبارات مرور في الكود ولا في السجلات: كل سرّ
يأتي من ملف يحقنه المخزن (vault) أو سرّ GitHub، ويُشار إليه بالاسم فقط.

## القطع

| الملف | الدور |
| --- | --- |
| `backup.sh` | نسخة واحدة: تفريغ + بيان (عدد وبصمة كل جدول) + تشفير GPG AES256 + رفع اختياري + تسجيل الحالة |
| `restore.sh` | فك التشفير، تحقق من البصمات، استعادة في قاعدة جديدة، مطابقة البيان — أو رفض بلا استثناء |
| `restore-drill.sh` | التمرين الشهري: أحدث أرشيف إلى قاعدة مؤقتة، إثبات المطابقة، ثم حذفها وتسجيل النتيجة |
| `pre-deploy.sh` | غلاف «قبل النشر»: يستدعي `backup.sh` بسبب `pre-deploy` قبل أي ترحيل إنتاجي |
| `verify-backup.sh` | فحص سريع لسلامة أرشيف بعد نسخه أو رفعه، بلا استعادة |

## الجدولة

| المهمة | التكرار | التفعيل |
| --- | --- | --- |
| نسخة مجدولة | أسبوعيًا | سطر cron في تغيير التوصيل (wiring.diff)، معطّل حتى يعتمد المالك الوجهة والأسرار |
| نسخة قبل النشر | قبل كل نشر إنتاجي | خطوة في تدفق production ضمن wiring.diff، معطّلة |
| تمرين استعادة | شهري | سطر cron ثانٍ في wiring.diff، معطّل |

## الأسرار (مراجع فقط، لا قيم هنا أبدًا)

| المتغير | المصدر |
| --- | --- |
| `BACKUP_PASSPHRASE_FILE` | ملف عبارة التشفير (mode 600) من المخزن؛ في CI سرّ `BACKUP_PASSPHRASE` يُكتب لملف مؤقت |
| `BACKUP_SOURCE_PGURI` | سرّ `PRODUCTION_DB_URI` (قراءة النسخة) |
| `BACKUP_STATE_PGURI` | السرّ نفسه: تسجيل الحالة عبر دالتَي 0103 |
| `BACKUP_UPLOAD_HOOK` | وجهة الرفع الخارجي بعد أن يعتمدها المالك (مثل rclone إلى Drive) |

## قواعد

- النسخة لا تُحسب إلا ببيانها وبصمتها مسجّلتين؛ أي فشل يسجَّل فشلًا ويخرج بغير صفر.
- الاستعادة ترفض قاعدة فيها جداول إلا بإذن صريح، ولا تُسمّى استعادةً قبل مطابقة العدد والبصمة لكل جدول.
- التمرين لا يُسمّى تصديرًا إنتاجيًا: التمارين المحلية تجري على بيانات مصطنعة بالكامل.
- الوجهة المعتمدة هي Drive الخاص بحساب gm.by3h@gmail.com. الجدولة والربط الدائم لم يُفعّلا بعد؛ لا يُحسب البند حيًّا بمجرد اعتماد الوجهة.

## حدود هذه الحزمة المحلية

- لا تفعيل حي ولا رفع حقيقي. الوجهة معتمدة، لكن يلزم إثبات الربط الدائم والجدولة. سياسة الاحتفاظ المقترحة غير معتمدة والحذف غير موصول.
- `BACKUP_ORGANIZATION_ID` يربط سجل الحالة بفندق محدد. السجل العام غير المربوط لا يظهر لأي مالك فندق.
- النسخة الحالية تفريغ PostgreSQL فقط. ملفات Supabase Storage، أسرار التشفير الخارجية وإعدادات Auth تحتاج مسارًا مستقلاً معتمدًا، وليست ضمن إثبات هذا التمرين.
- البيان والتفريغ يشتركان في لقطة repeatable-read مصدّرة واحدة. اختبار الكتابات المتزامنة ما زال مطلوبًا قبل اعتماد الإنتاج.
- مرجع نجاح الرفع لا يثبت قراءة النسخة من الوجهة. يلزم استرجاع مستقل من الوجهة قبل قبول التخزين الخارجي.
- البيانات المؤقتة تزال بـ rm، ولا ندّعي مسحًا آمنًا للقرص. يلزم قرص مؤقت مشفّر للتشغيل الحي.

## إضافات الجولة المحلية الثانية (بند 7.1)

| الملف | الدور |
| --- | --- |
| `prune.sh` | الاحتفاظ: يجري تجريبيًا افتراضيًا؛ الحذف فقط مع `BACKUP_PRUNE_APPLY=1`. المقترح (يعتمده المالك): كل نسخة آخر 35 يومًا، وأحدث نسخة مجدولة من كل شهر حتى 12 شهرًا، ولا أقل من 4 نسخ. لا يحذف إن لم يكن `latest.json` نجاحًا. لا يلمس إلا أسماء الأرشيف المطابقة. |
| `verify-remote.sh` | تنزيل نسخة جديدة من الوجهة عبر `BACKUP_FETCH_HOOK` ثم فك التشفير وفحص البصمة وقراءة فهرس التفريغ، ومقارنة البايتات بالأصل المحلي إن وُجد. نجاح الرفع وحده ليس إثباتًا. |
| `restore-preflight.sh` | يستدعيه `restore.sh` قبل الاستعادة: كل امتداد يحتاجه التفريغ يجب أن يتوفر في الهدف. |
| `coverage-report.sh` | يطبع مخططات التفريغ وما لا تغطيه النسخة. |
| `drive-hook.example.sh` | مثال فقط لخطافَي الرفع والتنزيل عبر rclone إلى Drive الخاص؛ رمز rclone يضبطه المالك على المضيف ولا يدخل المستودع. |

الاستعادة تغطي المخطط والبيانات والامتدادات (من التفريغ نفسه) وتُثبت العدد والبصمة لجداول public فقط.
غير مغطى ولا مُثبت: إعدادات Supabase Auth ومستخدموه خارج ما في التفريغ، وملفات Storage (الكائنات)، وكود Edge وأسرارها،
وعبارة التشفير. التمارين الحية الأولى (أسبوعي وشهري) لم تجرَ بعد؛ الاختبارات هنا محلية بلا خادم قاعدة بيانات
(أدوات pg مُستبدلة) وتثبت منطق الاحتفاظ والتحقق والرفض فقط، أما التمرين الكامل فسجله في acceptance/backup-drill-2.

## الجاهزية: محلي مقابل خدمة تشغيلية

| العنصر | الحالة |
| --- | --- |
| backup / restore / drill / verify-backup / prune / verify-remote / preflight | مكتوبة، واختبارات BK01-10 محلية (أدوات pg مُستبدلة، gpg حقيقي) تنجح |
| تفريغ واستعادة فعليان على PostgreSQL محلي | نجحا بـ117 جدولًا و3315 صفًا مصطنعًا (evidence/backup.log وrestore.log) |
| ملف التشغيل `.github/workflows/backup.yml.proposed` | مقترح معطّل، لا يُحمَّل ولا يملك جدولًا فعالًا |
| الحذف التلقائي | غير موصول؛ `prune.sh` يجري تجريبيًا، وأرقام الاحتفاظ مقترحة غير معتمدة |
| خطاف الرفع والتنزيل على Drive الخاص | مثال فقط؛ لم يُركَّب ولم يُجرَّب |
| أول نسخة أسبوعية حية، تنزيل وتحقق، تمرين شهري، عرض «آخر نسخة» للمالك، تنبيه عند الفشل | لم يحدث أي منها: البند ليس خدمة تشغيلية بعد |
| Auth (المستخدمون والإعدادات) وStorage (الكائنات) وكود Edge وأسرارها وعبارة التشفير | خارج النسخة والإثبات، ويلزم لكل منها مسار منفصل معتمد |
| مطابقة التمرين | جداول public فقط (عدد وبصمة)؛ الامتدادات تُفحص توفرها قبل الاستعادة |
| الوجهة | تُذكر معتمدة في الوثائق، لكنها لم تُستخدم ولم يُتحقق من الوصول إليها من هذا العمل |

اختبارات BK11-17 تفحص ملف التشغيل المقترح محليًا (معطّل، بلا جدول، بلا حذف، الأسرار عبر env فقط، التنظيف دائمًا،
خطوة PG غير المثبتة تفشل عمدًا، وخطاف Drive غير موجود في المستودع فيفشل التفعيل حتى يركّبه المشغّل). هذه جاهزية محلية
وليست خدمة نسخ تشغيلية.
