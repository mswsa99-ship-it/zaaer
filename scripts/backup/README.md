# النسخ الاحتياطي والاستعادة — بند 7.1 (O4 وT6)

نسخة مشفّرة أسبوعية وقبل كل نشر، وتمرين استعادة شهري، و«آخر نسخة» ظاهرة للمالك في الإدارة من حالة
موثّقة في قاعدة البيانات (ترحيل 0103). لا مفاتيح ولا عبارات مرور في الكود ولا في السجلات: كل سرّ
يأتي من ملف يحقنه المخزن (vault) أو سرّ GitHub، ويُشار إليه بالاسم فقط.

## القطع

| الملف | الدور |
| --- | --- |
| `backup.sh` | نسخة واحدة: تفريغ + بيان (عدد وبصمة كل جدول) + تشفير GPG AES256 + رفع اختياري + تسجيل الحالة |
| `restore.sh` | فك التشفير، تحقق من البصمات، استعادة في قاعدة جديدة، مطابقة البيان — أو رفض بلا استثناء |
| `restore-drill.sh` | التمرين الشهري: أحدث أرشيف إلى قاعدة مؤقتة، إثبات المطابقة، ثم حذفها وتسجيل النتيجة |
| `pre-deploy.sh` | غلاف «قبل النشر»: يستدعي `backup.sh` بسبب `pre-deploy` قبل أي ترحيل إنتاجي |
| `verify-backup.sh` | فحص سريع لسلامة أرشيف بعد نسخه أو رفعه، بلا استعادة |

## الجدولة

| المهمة | التكرار | التفعيل |
| --- | --- | --- |
| نسخة مجدولة | أسبوعيًا | سطر cron في تغيير التوصيل (wiring.diff)، معطّل حتى يعتمد المالك الوجهة والأسرار |
| نسخة قبل النشر | قبل كل نشر إنتاجي | خطوة في تدفق production ضمن wiring.diff، معطّلة |
| تمرين استعادة | شهري | سطر cron ثانٍ في wiring.diff، معطّل |

## الأسرار (مراجع فقط، لا قيم هنا أبدًا)

| المتغير | المصدر |
| --- | --- |
| `BACKUP_PASSPHRASE_FILE` | ملف عبارة التشفير (mode 600) من المخزن؛ في CI سرّ `BACKUP_PASSPHRASE` يُكتب لملف مؤقت |
| `BACKUP_SOURCE_PGURI` | سرّ `PRODUCTION_DB_URI` (قراءة النسخة) |
| `BACKUP_STATE_PGURI` | السرّ نفسه: تسجيل الحالة عبر دالتَي 0103 |
| `BACKUP_UPLOAD_HOOK` | وجهة الرفع الخارجي بعد أن يعتمدها المالك (مثل rclone إلى Drive) |

## قواعد

- النسخة لا تُحسب إلا ببيانها وبصمتها مسجّلتين؛ أي فشل يسجَّل فشلًا ويخرج بغير صفر.
- الاستعادة ترفض قاعدة فيها جداول إلا بإذن صريح، ولا تُسمّى استعادةً قبل مطابقة العدد والبصمة لكل جدول.
- التمرين لا يُسمّى تصديرًا إنتاجيًا: التمارين المحلية تجري على بيانات مصطنعة بالكامل.
- وجهة التخزين النهائية وإذن النسخ الحي ما زالا بانتظار قرار المالك؛ البند لا يُحسب «حيًّا» قبل التفعيل.

## حدود هذه الحزمة المحلية

- لا تفعيل حي ولا رفع حقيقي. يلزم اعتماد وجهة التخزين وسياسة الاحتفاظ والصلاحيات.
- `BACKUP_ORGANIZATION_ID` يربط سجل الحالة بفندق محدد. السجل العام غير المربوط لا يظهر لأي مالك فندق.
- النسخة الحالية تفريغ PostgreSQL فقط. ملفات Supabase Storage، أسرار التشفير الخارجية وإعدادات Auth تحتاج مسارًا مستقلاً معتمدًا، وليست ضمن إثبات هذا التمرين.
- البيان والتفريغ يشتركان في لقطة repeatable-read مصدّرة واحدة. اختبار الكتابات المتزامنة ما زال مطلوبًا قبل اعتماد الإنتاج.
- مرجع نجاح الرفع لا يثبت قراءة النسخة من الوجهة. يلزم استرجاع مستقل من الوجهة قبل قبول التخزين الخارجي.
- البيانات المؤقتة تزال بـ rm، ولا ندّعي مسحًا آمنًا للقرص. يلزم قرص مؤقت مشفّر للتشغيل الحي.
